# Nightprint — product context

Context for the marketing and SEO skills (`ai-seo`, `schema-markup`). Rules for the site itself are
in the `nightprint-seo` skill; scope and roadmap in `docs/PLAN.md`.

## Product

- **Nightprint** (nightprint.dev): software architecture concepts drawn as interactive 3D machines in
  the browser. A request travels through the machine step by step; "what if" switches change the
  machine and show what the pattern protects you from. Each machine has a bill of parts, a title block
  with its reference, and a short article with sources.
- Site language: English. Free, no account, no ads, no pricing. There is nothing to sell: the goals
  are reach, citations and a public portfolio, built in public.
- Status (October 2026): pre-launch. MCH-001 (hexagonal architecture) first, then one machine a week.
- Author: Ewen, posting the build on X as [@ewenlq](https://x.com/ewenlq).

## Audience

- Developers, junior to senior, who want to understand why an architecture pattern exists.
- Tech leads and teachers who need a clear picture to explain a pattern to a team.

## Positioning

- The only explainer that combines real 3D, software-architecture patterns, guided scenarios and
  "what if" switches.
- Accurate and sourced: each machine is checked against a reference (e.g. Cockburn, 2005, for
  hexagonal architecture) and never shows a behaviour the real system does not have.
- What people use instead: articles and static diagrams, interactive 2D essays, AI-generated SVG
  machines, system-design simulators.

## Target queries (one machine page answers each group)

- MCH-001: "hexagonal architecture", "hexagonal architecture explained", "ports and adapters",
  "what is a port in hexagonal architecture", "driving vs driven adapters",
  "hexagonal architecture example".
- Upcoming (no page yet, do not target): JavaScript event loop, domain-driven design, offline-first
  sync, CQRS and event sourcing, React rendering, Redis cache-aside, Kafka partitions and consumer
  groups.

## Voice

- Short, active sentences, no hype, no emoji. Steps are titled by what happens ("Postgres answers").
- Technology names in text, never logos. Business examples stay generic (an order, a payment).

## Do not

- Invent statistics, reviews, testimonials or awards.
- Create comparison pages, listicles, a pricing page or `pricing.md`.
- Write content aimed at AI systems instead of people.
